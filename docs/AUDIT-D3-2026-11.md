## What the attacker had before this session

1. **The minted matrix.** A thief clones the repo, re-runs the committed generator over their own identity, and ships a build whose D0-D2 all agree with each other. The previous session's tooling (6325e2f) could DETECT this from outside, but the module itself still reported `status=verified` — the runtime had no third leg.
2. **The regenerable release channel.** Every release sidecar (SHA-512, BLAKE3, SHAKE256) is recomputable by whoever holds the archive bytes. A MITM on the release page — or a hijacked session re-cutting archive + sidecars together — passed every digest check by construction.

## What closes each hole

### C2 — D3, the publisher signature (commit 87af298)

- The D3 message is the length-framed clear bytes of both layers (u32le length prefixes, domain `bmi-stellar/depth-matrix/v1`), signed with the publisher's Ed25519 key. The private seed lives offline (generated fresh this session, in `download/`, never printed or committed); the module carries only the public key and the signature.
- The runtime verdict becomes three-fold: fingerprints (D2), identity binding, and publisher signature. Verdict space: `verified` / `unsigned` (the empty-signature rotation state — a known state, not evidence of tampering) / `tampered`.
- The verifier is self-contained bigint arithmetic (extended homogeneous coordinates, strict `s < L`), zero new dependencies — the app keeps its zero-curve footprint. During development a precedence bug (`& `binding looser than `===`) threw on every point decode and was caught because the D3 status refused to go green; the fix is commented as load-bearing in `edDecode`.
- Cross-checked from three implementations: the TypeScript runtime, the pure-Python RFC 8032 reference (`generate-provenance-words.py --check`, now section [13] of the wholesale gate-keepers lane), and `openssl pkeyutl -verify` (Ed25519 is deterministic — all three produce the identical signature bytes).
- The gate (`check-signature.ts`) pins `EXPECTED_OWNER_PUBLIC_KEY` and verifies the signature over its own recomputed payload: swapping the module's constants AND the module's key still stops at a visible gate diff.

### C1b — the artifact gate (commit 9c28752)

- The tree gates proved the source; `check-artifact-provenance.ts` proves the shipped bytes. Over every text file the build emitted: zero plaintext identity (manifest, authors, handle, contact, and their fragments), the D3 pair present, the masked words present (as minified decimal BigInt literals), the PWA field parity.
- The gate's first run caught its own design error — the D3 domain separator was probed as identity when it is public protocol material (the brand-prose class). Fixed with the boundary documented in the needle list; the lesson is recorded in INNOVATIONS entry 34.

### C3 — the signed release channel (this change)

- **The tag-signing contract.** `release.yml` now refuses to publish unless `git tag -v` shows a good signature from the key pinned in the `RELEASE_GPG_PUBLIC_KEY` repository secret (armored public key — public material by definition; a plain repository variable works as the fallback, so either tab serves; rotation is a settings change plus a workflow edit, both auditable). Fail closed while neither is set: the error message names the setting and the reason.
- **The attestation lane.** `actions/attest-build-provenance` (SHA-pinned, `977bb373...` = v3) binds both release archives to the repository and workflow run through the GitHub OIDC identity; the attestation lands in the public transparency log and verifies offline with `gh attestation verify`. The permissions block gains `id-token: write` + `attestations: write` for exactly this flow.
- Threat-model honesty: the tag contract protects against a forged/unwitting tag, the attestation protects against release-page tampering post-publish. An attacker who controls the GitHub account itself can still cut a new tag — but it must be GPG-signed by the owner's key (they cannot) or the workflow fails closed, so the forgery surface shrinks to "compromise the owner's Proton GPG key", the same surface as every signed-release project in existence.

## Honest limits (unchanged in kind, documented in place)

- D3 is provenance and tamper evidence, not DRM. The public key and signature ride the bundle; an attacker who understands the scheme can strip the whole matrix — but stripping means editing the gate (a visible diff), and the release channel no longer honors a stripped tree with a valid signed tag.
- The GPG tag contract requires the owner to actually sign tags. Until `RELEASE_GPG_PUBLIC_KEY` is set, the release lane fails closed by design — that is the correct failure, not a bug.
- Memory forensics remains out of scope (the materialized plaintext lives in process memory by design of the -V/About surfaces).
